# 部署运维指南

## 一、生产环境要求

| 组件 | 最低配置 | 推荐配置 |
|------|---------|---------|
| CPU | 4 核 | 8 核+ |
| 内存 | 8 GB | 16 GB+ |
| 磁盘 | 50 GB | 200 GB+ (SSD) |
| 操作系统 | Ubuntu 20.04+ / CentOS 7+ / Windows Server 2019+ |
| Node.js | 18 LTS | 20 LTS |
| PostgreSQL | 16+ | 16+ (含 pgvector) |
| Python | 3.10+ | 3.10+ (模型训练) |
| 浏览器 | Chromium (Playwright) | — |

## 二、环境准备

### 2.1 安装 Node.js

```bash
# Ubuntu
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# 验证
node -v  # ≥ 18
npm -v
```

### 2.2 安装 PostgreSQL + pgvector

```bash
# Ubuntu
sudo apt install postgresql-16 postgresql-16-pgvector

# 创建数据库
sudo -u postgres psql
CREATE DATABASE training_exercises;
CREATE USER liangwenqing WITH PASSWORD 'liangwenqing';
GRANT ALL PRIVILEGES ON DATABASE training_exercises TO liangwenqing;

# 启用 pgvector
\c training_exercises
CREATE EXTENSION IF NOT EXISTS vector;
```

### 2.3 安装 Chromium（Playwright）

```bash
cd code/backend
npx playwright install --with-deps chromium
```

### 2.4 安装 Python 训练依赖（可选）

```bash
python -m pip install sentence-transformers torch
```

仅当需要使用"模型训练"功能时需要，用于微调 Embedding 模型。

### 2.5 安装 Ollama（可选）

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen3:14b
ollama pull qwen3:4b
```

## 三、构建部署

### 3.1 后端构建

```bash
cd code/backend
npm install
npm run build        # tsc 编译到 dist/
```

### 3.2 前端构建

```bash
cd code/frontend
npm install
npm run build        # vite build 到 dist/
```

### 3.3 生产启动

后端直接运行编译后的 JS：

```bash
cd code/backend
node dist/index.js
```

前端静态文件使用 Nginx 托管：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态文件
    root /path/to/code/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # WebSocket 代理
    location /socket.io/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 86400;
    }
}
```

## 四、进程管理（推荐 PM2）

### 4.1 安装 PM2

```bash
npm install -g pm2
```

### 4.2 启动后端


### 4.3 常用命令

```bash

pm2 stop aitraining-api     # 停止
pm2 monit             # 实时监控
```

## 六、监控指标

### 6.1 关键监控项

| 指标 | 告警阈值 | 说明 |
|------|---------|------|
| CPU 使用率 | > 80% | 爬虫并发过高 |
| 内存使用率 | > 85% | Chromium 内存泄漏 |
| DB 连接数 | > 45 | 接近连接池上限 |
| 爬虫任务失败率 | > 10% | 反爬升级或网络异常 |
| API 响应时间 | > 5s | 数据库或 LLM 瓶颈 |

### 6.2 数据库连接池监控

## 九、故障排查

### 爬虫任务卡住不动

1. 检查浏览器进程：`ps aux | grep chromium`
2. 清理残留进程：`pkill -f chromium`
3. 检查代理池状态
4. 查看 WebSocket 连接是否正常

### 数据库连接池耗尽

1. 检查活跃连接：`SELECT count(*) FROM pg_stat_activity WHERE datname='training_exercises'`
2. 临时增加 `max` 参数
3. 检查是否有未释放的连接（事务未提交）

### LLM 调用失败

1. 检查 API Key 是否有效
2. 检查网络连通性
3. Ollama：确认服务运行 `curl http://localhost:11434/api/tags`
4. 云端：检查账户余额和速率限制

### WebSocket 断连

1. 检查 Nginx 超时设置（`proxy_read_timeout`）
2. 客户端会自动重连，重连后重新订阅运行中的任务

## 十、性能优化建议

| 优化项 | 方法 | 效果 |
|--------|------|------|
| 爬虫并行度 | 调整 `maxConcurrency`（最大 5） | 提升采集速度 |
| LLM 批量处理 | 数据增强支持并行处理 | 减少总时间 |
| 数据库索引 | 参考数据库设计文档中的索引建议 | 加速查询 |
| 前端静态资源 | Nginx 开启 gzip + 缓存 | 减少加载时间 |
| Chromium 内存 | 使用 `--disable-dev-shm-usage` 等标志 | 减少崩溃 |
| 代理池 | 配置付费代理提升稳定性 | 减少 IP 封锁 |
