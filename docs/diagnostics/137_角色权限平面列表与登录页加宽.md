## 二、角色权限归入菜单平面列表

### 2.1 问题演进

**第一版**：权限和菜单是两个独立区域（卡片网格 + 树），用户反馈两者缺乏关联。

**第二版**：将权限嵌入 `el-tree` 的自定义 slot，在每个树节点内渲染权限复选框。但 Element Plus 的 `el-tree-node__label` 是 inline span，内部 CSS 受限严重，权限始终挤在一起重叠，`flex-direction: column` 等样式无法生效。

**第三版（最终）**：完全放弃 `el-tree`，改用自定义平面列表。

### 2.2 数据结构

```typescript
interface FlatItem {
  type: 'menu' | 'perm'
  key: string       // v-for 唯一键
  menuId: number    // 所属菜单 ID
  permId?: number   // 权限 ID（仅 perm 类型）
  depth: number     // 缩进层级（0 = 顶级菜单）
  name: string
  path?: string     // 菜单路径
  action?: string   // 权限操作（如 create/edit/delete）
}

const flatMenuPermList = computed<FlatItem[]>(() => {
  const result: FlatItem[] = []
  function walk(menus: any[], depth: number) {
    for (const m of menus) {
      // 先插入菜单行
      result.push({ type: 'menu', key: `menu-${m.id}`, menuId: m.id, depth, name: m.name, path: m.path })
      // 再插入该菜单关联的权限行
      for (const p of getPermsForMenu(m)) {
        result.push({ type: 'perm', key: `perm-${p.id}`, menuId: m.id, permId: p.id, depth: depth + 1, name: p.name, action: p.action })
      }
      // 递归子菜单
      if (m.children?.length) walk(m.children, depth + 1)
    }
  }
  walk(menuTree.value, 0)
  return result
})
```

### 2.3 模板结构

每个 FlatItem 渲染为独立 flex 行，通过 `paddingLeft` 表达层级缩进：

```
菜单与权限
├── 系统管理                    [菜单 checkbox]
│   ├── 用户管理  /system/users [菜单 checkbox]
│   │   ├── 创建用户  create    [权限 checkbox]
│   │   ├── 编辑用户  edit      [权限 checkbox]
│   │   ├── 删除用户  delete    [权限 checkbox]
│   │   └── 查看用户  view      [权限 checkbox]
│   ├── 角色管理  /system/roles [菜单 checkbox]
│   │   ├── 创建角色  create    [权限 checkbox]
│   │   └── ...
```

### 2.4 样式要点

- 每行 `display: flex; align-items: center; min-height: 34px; gap: 8px`
- 缩进：`paddingLeft: 12 + depth * 24` px
- 菜单行粗体，权限行细体 + 虚线顶边
- 悬停行浅紫背景
- 权限操作标签：10px 紫色胶囊 `#667eea`
- 菜单路径标签：11px 灰色等宽字体
- 容器 `max-height: 420px; overflow-y: auto`

### 2.5 移除项

- `el-tree` 及其 `menuTreeRef`、`onMenuCheck`
- 原 `menu-node-content` / `menu-node-perms` 等 CSS
- 独立的"权限分配"卡片网格区域
