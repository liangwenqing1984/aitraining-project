# 智能查询表格宽度修复与帮助FAQ补全

## 概述
本次变更涉及两个模块：修复智能查询结果表格过宽导致用户问题被遮挡的 UI 问题，以及帮助文档 FAQ 补充 pgvector 和模型大小相关问答。

## 一、智能查询表格宽度修复

### 需求/问题
智能查询页面（`/query`）中，当 NL 查询结果列数较多时，结果表格宽度超出消息容器，迫使页面出现水平滚动条，用户需要向右拖动才能看到自己的问题文本。

### 实现/修复
修改 `code/frontend/src/views/query/Index.vue` 两处 CSS：

1. `.message-body` 添加 `min-width: 0` — flex 布局中 flex 子项默认 `min-width: auto`，会为容纳子内容而撑破 `max-width: 75%` 约束。设置 `min-width: 0` 后强制遵守最大宽度。

2. `.message-table` 添加 `overflow-x: auto; max-width: 100%` — 当结果表格列数较多时，表格在消息气泡内部水平滚动，不再撑宽整个页面。

## 二、帮助文档 FAQ 补全

### 需求/问题
- 用户询问 pgvector 在系统中的作用和向量数据存储位置
- 用户询问模型训练磁盘大小（522.6MB）与 Ollama 部署大小（274MB）不一致的原因

### 实现/修复
修改 `code/frontend/src/views/Docs.vue`：

1. **文本向量化 FAQ**：新增 pgvector 问答，说明 4 类向量表（job_embeddings / doc_embeddings / resume_embeddings / training_embeddings）、3 种应用场景（语义搜索 / AI 问答 / 简历匹配）、IVFFlat 余弦索引加速原理和降级策略。

2. **语义模型训练 FAQ（Q17）**：新增模型文件大小差异问答，解释磁盘存储的是完整训练产物（FP32 权重 + 优化器状态 + 检查点），Ollama 存储的是 GGUF 4bit 量化格式，体积约为原始的一半，这是正常行为而非 bug。
