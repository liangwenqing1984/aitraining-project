# AI 简历筛选系统 — 4 模块完整实现

## 概述

对照 [151_AI简历筛选系统需求分析与架构设计.md](151_AI简历筛选系统需求分析与架构设计.md) 第七章的 4 个待建模块，分 4 个 Phase 完成简历筛选系统的全部功能：简历结构化解析、内部岗位 JD 管理、匹配打分引擎、HR 操作后台。

## 一、Phase 1: 简历结构化解析（P0 基础设施）

### 需求

将非结构化简历（PDF/Word/TXT）→ 提取纯文本 → LLM 解析为 18 个结构化字段 → 存储 → 异步生成语义向量。

### 实现

**数据库** — `sp_resumes` 表：
- 基础字段: name, email, phone, education_level, school, major, graduation_year, work_years
- 向量字段: embedding vector(768)（pgvector 条件创建，非 pgvector 环境跳过）
- JSONB 字段: skills, skill_levels, projects, certifications, languages
- 求职意字段: desired_position, desired_city, desired_salary_min/max, job_type
- 解析元数据: parse_confidence, parsed_by_model

**LLM Prompt** — `services/llm/prompts.ts`：
- `RESUME_PARSE_SYSTEM`: 专业简历解析专家系统提示词，规范化学历等级（高中/大专/本科/硕士/博士），提取技能及熟练度
- `RESUME_PARSE_USER`: 截断至 4000 字符传入 LLM

**解析服务** — `services/llm/resumeParser.ts`：
- `parseResumeStructure()`: 调用 LLM（taskType='resume-parse', responseFormat='json', temperature=0.1）
- 自动处理 LLM 返回的 markdown code block 包裹
- 下划线→驼峰字段映射

**文件提取** — `services/llm/resumeParser.ts`：
- `extractResumeText()`: 支持 PDF（pdf-parse）、DOCX（mammoth）、TXT（UTF-8/GBK 自动检测）
- Multer memoryStorage 单文件上限 10MB
- 中文文件名修复: `Buffer.from(..., 'latin1').toString('utf8')`

**API**:
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/rag/resume/parse` | 上传文件 → 提取文本 → LLM 结构化 → 存储 + 异步生成 embedding |
| GET | `/api/rag/resume/:id` | 获取简历详情 |
| GET | `/api/rag/resumes` | 分页列表（keyword 搜索） |
| PUT | `/api/rag/resume/:id` | 更新简历字段 |
| DELETE | `/api/rag/resume/:id` | 删除简历 |

**前端** — `ResumeScreening.vue`：
- 三模式切换: 职位匹配 / 内部筛选 / 结构解析
- 解析结果展示: el-descriptions（基本信息 + 求职意向）、el-collapse（项目经验）、el-tags（技能/证书/语言）

## 二、Phase 2: 内部岗位 JD 管理（P1）

### 需求

HR 录入本单位内部岗位，设定硬性筛选规则（学历、经验、必备技能、技能匹配模式）。

### 实现

**数据库** — `sp_internal_jobs` 表：
- 基础信息: title, department, description, requirement
- 硬性规则: education_required, experience_years_min/max, required_skills, preferred_skills, skill_match_mode(all/any)
- 招聘信息: headcount, salary_min/max, job_type, status(open/closed/filled), city_preferred
- 向量字段: embedding vector(768), embedding_text（文本快照，用于重新生成向量时去重）

**CRUD 服务** — `services/internalJobService.ts`：
- `createInternalJob()`/`updateInternalJob()`: 写入后异步生成 embedding（拼接 title+description+requirement → generateEmbedding）
- `updateInternalJob()`: 仅 description 变更时重新生成 embedding（避免无效计算）
- `deleteInternalJob()`: 直接删除

**API**:
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/internal-jobs` | 分页列表（keyword/status 过滤） |
| POST | `/api/internal-jobs` | 新增岗位 |
| GET | `/api/internal-jobs/:id` | 获取岗位详情 |
| PUT | `/api/internal-jobs/:id` | 更新岗位 |
| DELETE | `/api/internal-jobs/:id` | 删除岗位 |

**前端** — `InternalJobs.vue`：
- 表格列表（搜索栏 + 状态筛选 + 分页）
- 新增/编辑对话框，分段配置: 基本信息 → 硬性规则配置区（学历选择器、经验年限范围、技能多选含创建新技能、匹配模式 any/all、城市多选）→ 其他信息

**菜单种子**: 系统管理 > 内部岗位 (sort_order=7)

## 三、Phase 3: 匹配打分引擎（P0 核心）

### 需求

融合硬性规则过滤 + 向量语义相似度 + 技能加分，输出可解释的综合打分结果。

### 打分公式

```
totalScore = hardRuleScore(40) + similarityScore(40) + skillBonus(20)

hardRuleScore = educationPassed ∧ experiencePassed ∧ skillsPassed ? 40 : 0
similarityScore = cosine_similarity * 40   (0-100% → 0-40分)
skillBonus = required匹配*3 + preferred匹配*2，封顶20分

totalScore ≥ 80 → strong | ≥ 60 → moderate | ≥ 40 → weak | else → rejected
```

按 hard_rules 全部通过者优先排序，同类按总分降序。

### 硬性规则检查

| 规则 | 逻辑 |
|------|------|
| 学历 | 等级映射（高中:1 大专:2 本科:3 硕士:4 博士:5），候选人 ≥ 要求即通过 |
| 经验 | 候选人工作年限 ≥ 岗位最低要求 |
| 技能 (all) | 所有必备技能均匹配 |
| 技能 (any) | 至少一个必备技能匹配 |

### 实现

**匹配服务** — `services/matchingService.ts`：
- `screenResumeAgainstJobs()`: 获取简历数据+embedding → 查询 open 状态内部岗位 → 逐个计算评分
- `checkHardRules()`: 独立函数，可复用
- `cosineSimilarity()`: 纯 JS 实现，避免 DB 依赖
- 支持实时 fallback: 岗位无预存 embedding 时，用 embedding_text 现场生成
- 返回完整评分明细（scoreBreakdown: hardRuleScore/similarityScore/skillBonus）

**API**: `POST /api/rag/resume/screen`
```json
// 请求: { resumeId?, resumeText?, internalJobId?, limit?, minScore? }
// 响应: { resumeName, totalJobsCompared, results: [{ hardRules, softMatch, totalScore, scoreBreakdown, recommendation }] }
```

**前端** — `ResumeScreening.vue` 内部筛选模式：
- 上传简历自动结构化解析 → 下拉选择目标岗位（可选全部）→ 点击"开始智能筛选"
- 结果卡片: 岗位名 + 部门 + 推荐等级标签 + 综合得分（大号数字，按等级着色）
- 评分明细折叠面板: 硬性规则逐项检查 ✓/✗ + 语义相似度百分比 + 匹配技能列表 + 得分分解

## 四、Phase 4: HR 操作后台完善（P1）

### 需求

批量上传简历、筛选结果持久化与历史查询、Excel 导出、简历库管理。

### 4.1 数据库

**`sp_screening_results` 表**:
- 外键: resume_id → sp_resumes, internal_job_id → sp_internal_jobs（均为 SET NULL on delete）
- 反范式冗余: resume_name, internal_job_title, department（加速列表查询）
- 评分字段: total_score, recommendation, hard_rules_passed, education_passed, experience_passed, skills_passed
- 相似度/加分: similarity, skill_bonus
- 完整快照: score_breakdown(JSONB), full_result(JSONB)
- 审计字段: created_by, created_at

### 4.2 批量操作

| API | 说明 |
|-----|------|
| `POST /api/rag/resume/batch-parse` | 多文件批量上传解析（multer array 最多 20 个），逐个调用 LLM 结构化 → 异步生成 embedding，返回成功/失败明细 |
| `DELETE /api/rag/resumes/batch` | 按 ID 列表批量删除 |

### 4.3 筛选历史

| API | 说明 |
|-----|------|
| `POST /api/rag/resume/screening/save` | 保存当前筛选结果到 sp_screening_results |
| `GET /api/rag/resume/screening/history` | 分页查询筛选历史（支持 resumeId/internalJobId 过滤） |

### 4.4 Excel 导出（exceljs）

| API | 说明 |
|-----|------|
| `GET /api/rag/resume/screening/export` | 导出筛选结果 Excel（12 列，含硬性规则逐项明细、推荐等级条件着色） |
| `GET /api/rag/resumes/export` | 导出简历库 Excel（20 列全字段、技能/证书数组展开为逗号分隔文本） |

导出特性:
- 表头蓝色背景白色加粗字体
- 推荐等级单元格按强度着色（绿色=强烈、黄色=一般、灰色=勉强、红色=不推荐）
- 文件名使用 RFC 5987 `filename*=UTF-8''` 编码避免中文乱码

### 4.5 前端新页面

**ResumeLibrary.vue** — 简历库管理：
- 顶部工具栏: 搜索（姓名/期望岗位/技能模糊匹配）+ 批量删除 + 导出Excel + 批量导入按钮
- 表格列: 选择框、ID、姓名、学历标签、工龄、技能标签（最多5个+溢出计数）、期望岗位、期望城市、电话、源文件、解析置信度进度条、入库时间、操作按钮
- 详情对话框: el-descriptions 展示全部 18 个字段 + 项目经验折叠面板
- 编辑对话框: 内联表单编辑（所有可编辑字段 + 学历/工作类型下拉选择器）
- 批量导入对话框: 多文件拖拽上传 → 开始解析 → 成功/失败明细表格
- 批量删除: 二次确认弹窗

**ResumeScreening.vue** — 增强：
- 解析/筛选模式支持多文件批量上传（el-upload multiple）
- 筛选完成后"保存到历史"和"导出 Excel"操作按钮

## 技术要点

### LLM 调用策略
- 简历解析使用 `taskType: 'resume-parse'` + `responseFormat: 'json'` + `temperature: 0.1` 确保输出稳定
- LLM 返回可能包裹 markdown code block，解析时自动剥离 ` ```json ... ``` `

### 向量生成策略
- 简历/岗位文本截断至 2000 字符（平衡精度与成本）
- embedding 采用异步非阻塞模式，不阻塞 HTTP 响应
- 岗位仅 description 变更时重新生成 embedding

### 数据库查询模式
- 所有 SQL 使用 `?` 占位符，由 db 封装层自动转为 `$1, $2` 格式
- 查询结果自动 `snake_case → camelCase` 转换
- 批量删除使用动态 IN 子句占位符生成

### 前端状态管理
- 三模式切换时自动清除旧结果避免数据混淆
- 多文件上传使用动态 `import()` 按需加载批量解析 API
- Excel 导出使用 Blob + URL.createObjectURL 浏览器下载
