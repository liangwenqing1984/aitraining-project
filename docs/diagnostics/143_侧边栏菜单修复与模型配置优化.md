# 侧边栏菜单修复与模型配置优化

## 概述

本次涉及侧边栏菜单 API 动态化的多项修复、首页卡片 hover 效果优化、模型配置页面 UI 和逻辑修复。

## 一、侧边栏菜单 API 动态化修复

### 问题
上轮将侧边栏硬编码菜单改为 API 动态获取后，出现一系列问题：
1. 图标组件被 Vue 深度响应式代理，控制台报警告
2. `ref is not defined` / `menuItems.find is not a function` 导致页面崩溃
3. API 响应拦截器已解包 `response.data`，但判断条件多套一层导致永远为 false

### 修复

| 问题 | 修复 |
|------|------|
| 图标响应式警告 | 用 `markRaw()` 包裹所有 Element Plus 图标，`shallowRef` 替代 `ref` 声明 `menuItems` |
| 页面崩溃 | 补回 `ref` 导入，`menuItems.find` 改为 `menuItems.value.find` |
| API 解包层次 | `res?.data?.success` → `res?.success`，`res.data.data` → `res.data` |
| API 故障兜底 | `menuItems` 初始值设为 `defaultMenuItems`，API 失败时侧边栏不空白 |

## 二、首页核心亮点卡片 hover 效果

### 需求
hover 时卡片背景变淡蓝色 + 增强立体感。

### 实现
- 用 `:deep(.el-card__body)` 穿透 Element Plus 内部样式设置 `background: #ecf5ff`
- 双层阴影：`0 8px 24px rgba(64,158,255,0.15)` 蓝色散射光 + `0 2px 6px rgba(0,0,0,0.08)` 底层暗影
- `translateY` 从 `-2px` 增加到 `-4px`

## 三、模型配置 UI 优化

### 卡片样式
- 右侧按钮图标统一显示 `+` 号，不再区分已配置/未配置
- 已配置供应商标题下方统一显示"点击配置"

### Ollama 模型列表
- 清空硬编码预设（`qwen3:14b` 等与本机不匹配），完全依赖 Ollama API 动态获取
- `editConfig` 编辑已有配置时增加 `fetchOllamaModels()` 调用
- catch 块增加 console.error 日志
