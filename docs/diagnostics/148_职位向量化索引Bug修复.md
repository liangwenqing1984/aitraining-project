# 职位向量化索引 Bug 修复

## 概述

修复 RAG 职位向量化索引的 4 个 Bug：去重缺失导致重复索引、错误阈值过低导致提前终止、控制器静默失败、前端轮询过早判定完成。

## 一、rag.ts — 去重跳过 + 错误阈值

### 需求/问题
`indexJobEmbeddings()` 每次执行都从头开始 embedding，不检查已有索引记录。152 条已向量化的记录被重复发送给 Ollama 生成 embedding，浪费算力。同时错误阈值设为 10，512 条记录中偶发 10+ 条失败即整体中止，导致约 115 条后终止。

### 实现/修复
- 在循环内增加 `alreadyIndexed.has(jobId)` 检查，已索引记录 `skipped++` 跳过
- 错误阈值从 10 提高到 50，中止前通过 WebSocket 发出进度通知
- 涉及文件：`code/backend/src/services/llm/rag.ts`

## 二、ragController.ts — WebSocket 完成/失败通知

### 需求/问题
`indexTask` 控制器使用 `.catch()` 静默吞掉异步错误，前端无法获知索引真正完成或失败。

### 实现/修复
- 引入 `io` 实例
- 异步调用改为 `.then().catch()` 链，成功时 emit `rag:indexCompleted`，失败时 emit `rag:indexFailed`
- 涉及文件：`code/backend/src/controllers/ragController.ts`

## 三、前端轮询 — 对比 enrichmentTotal 判断完成

### 需求/问题
`doIndex()` 轮询 `getRAGStats` 时，只要 `data.count > 0` 就判定完成并停止。实际 512 条记录刚索引几条就触发停止。

### 实现/修复
- 新增 `enrichmentTotal` 保存增强数据总数
- `onIndexTaskChange` 中从 enrichment 状态接口获取 total
- 轮询改为 `count >= targetCount` 判断完成
- 新增停滞检测：连续 3 次无增长判定异常结束并提示失败数量
- 涉及文件：`code/frontend/src/views/rag/Index.vue`
