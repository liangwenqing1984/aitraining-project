# 多模块优化总结：智能分析、智能查询、向量化索引

> 优化日期：2026-05-07 ~ 2026-05-08

## 一、智能分析模块

### 1.1 字段名兼容（commit `7503728`）

**问题**：51job 任务的智能分析报"CSV中缺少工作城市/职位名称字段"

**根因**：前端图表字段名硬编码智联格式（`工作城市`/`职位名称`/`公司性质`），51job 使用不同命名（`城市`/`岗位名称`/`企业类型`）

**修复**：
- 后端 `fileController.ts`：企业性质查找增加4级降级（`公司性质` → `企业类型` → 含`性质` → 含`企业类型`）
- 前端 `analysis/Index.vue`：城市/职位字段增加51job精确匹配 + 模糊匹配

### 1.2 topValues 生成条件（commit `87cfc67`）

**问题**：智联单城市任务511条数据，城市分布/职位分布/企业性质三个图表无数据

**根因**：`fileController.ts:312` 的 topValues 生成条件 `uniqueValues.size <= 200 && > 1`：
| 字段 | 唯一值数 | 违反条件 | 
|------|---------|---------|
| 工作城市 | 1 | `> 1`（单城市搜索） |
| 职位名称 | 460 | `≤ 200`（多职位搜索） |
| 公司性质 | 1 | `> 1`（511条仅1条有值） |

**修复**：
- 上限 `200 → 1000`（覆盖多职位场景）
- 下限 `> 1 → > 0`（覆盖单城市/单值场景）
- 前端诊断面板改为动态生成准确原因，不再误导显示"CSV中缺少字段"

### 1.3 raw_data 字段提取（commit `fd11033`）

**问题**：`analysisController.ts` 中 `getField()` 访问 `row.rawData`（camelCase），但 `sp_jobs` 表列名是 `raw_data`（snake_case）

**修复**：`row.rawData → row.raw_data || row.rawData`，兼容两种命名

## 二、智能查询模块（commit `fc61f67`）

### 2.1 LLM 只返回少量字段

**问题**：自然语言查询结果只显示3-5个字段，两张表大量关键字段缺失

**根因**：prompt 仅弱提示"列出 sp_jobs 的 company_name、job_name...等原始字段"，LLM 自行决定 SELECT 列

**修复**：`prompts.ts` 强化规则：
- 强制使用 `FROM sp_job_enrichments e LEFT JOIN sp_jobs j ON ...`
- SELECT 必须显式列出 sp_jobs 全部8字段 + sp_job_enrichments 全部14字段
- 禁止 `SELECT *`
- 统计查询也尽量保留全部字段

### 2.2 中文表头映射从未生效

**问题**：查询结果表头始终显示英文（如 `companyName`），中文映射 `columnLabelMap` 未起作用

**根因**：后端 `db.prepare().all()` → `convertRowsToCamelCase()` 自动将 PG 返回的 `company_name` → `companyName`，但前端 `columnLabelMap` 键名全部是 snake_case，28 个映射无一生效

**修复**：`columnLabelMap` 全部改为 camelCase 键名（`company_name` → `companyName` 等），移除不存在于查询结果中的 raw_data 子字段

## 三、向量化索引模块（commit `7fe20c3`）

### 3.1 未增强数据时无前端提示

**问题**：对未做 AI 增强的任务点击"开始向量化索引"，前端立即显示成功，后台静默失败（日志报错），用户只能等待轮询超时才知失败

**修复**：
- **后端** `ragController.ts`：`indexTask()` 返回 HTTP 200 前同步查询 `sp_job_enrichments`，无数据直接返回 400 + 引导信息
- **前端** `rag/Index.vue`：选择任务时即调 `getEnrichmentStatus` 检查，无增强数据时：
  - 显示黄色 Warning Alert：引导用户先做 AI 增强
  - 禁用"开始向量化索引"按钮
