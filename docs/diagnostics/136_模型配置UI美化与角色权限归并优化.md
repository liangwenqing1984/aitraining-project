## 二、模型配置对话框 UI 美化

### 2.1 设计规范对齐

将 LLMSettings.vue 的编辑/测试对话框与 4 个系统管理页面（用户/角色/权限/菜单）统一设计语言：

- **对话框头部**：渐变背景图标 + 标题（`dialog-header` / `dialog-header-icon`）
- **表单分区**：分节标题带图标（`form-section-title` / `section-icon`）
- **提供商选择**：`el-option-group` 分组（云端模型 / 本地模型）
- **任务分配**：卡片式 checkbox 网格，每个任务带图标 + 描述副标题
- **字段提示**：`field-hint` 灰色小字说明
- **底部按钮**：渐变主按钮 + 圆角（`dialog-footer`）
- **测试结果**：状态色编码（成功/失败/延迟）

## 三、Ollama 动态模型列表加载

### 3.1 问题

添加本地 Ollama 模型时，模型名称下拉框显示硬编码预设 `['qwen3:14b', 'qwen3:4b', ...]`，而非用户本地部署的实际模型。

### 3.2 解决方案

新建完整的前后端数据管道：

```
前端选择 Ollama
  → fetchProviderModels('ollama')
    → GET /api/llm/models/ollama
      → http://localhost:11434/api/tags (5s 超时)
        → 返回真实模型列表
```

### 3.3 修改文件

**后端 — llmController.ts** 新增控制器函数：

```typescript
export async function listProviderModels(req: Request, res: Response) {
  const provider = req.params.provider as LLMProvider
  // 校验 provider 有效性（9 种: openai/anthropic/ollama/deepseek/zhipu/qwen/baidu/bytedance/moonshot）

  if (provider === 'ollama') {
    // 直接调用 Ollama 本地 API
    const res = await fetch(`${baseUrl}/api/tags`, { signal: AbortSignal.timeout(5000) })
    // 返回 models[] → 提取 name 字段
  }

  // 云端模型：复用 healthCheck 获取 /v1/models
  const result = await llmService.healthCheck(provider)
  return res.json({ success: true, data: result.models })
}
```

**后端 — llmRoutes.ts** 新增路由：

```typescript
router.get('/models/:provider', llmController.listProviderModels)
```

**前端 — api/llm.ts** 新增 API 函数：

```typescript
export function fetchProviderModels(provider: string): Promise<ApiResponse<string[]>> {
  return api.get(`/llm/models/${provider}`)
}
```

**前端 — LLMSettings.vue** 核心逻辑：

```typescript
const providerModels = ref<string[]>([])
const loadingModels = ref(false)

// 动态模型列表：Ollama 用实时获取的，其他用预设
const availableModels = computed(() => {
  if (form.value.provider === 'ollama' && providerModels.value.length > 0) {
    return providerModels.value
  }
  return modelPresets[form.value.provider] || []
})

async function fetchOllamaModels() {
  loadingModels.value = true
  providerModels.value = []
  try {
    const res = await fetchProviderModels('ollama')
    if (res.success && Array.isArray(res.data)) {
      providerModels.value = res.data
    }
  } catch { /* 失败回退到预设 */ }
  finally { loadingModels.value = false }
}

// 切换提供商时触发
function onProviderChange(prov: string) {
  form.modelName = ''
  if (prov === 'ollama') fetchOllamaModels()
}
```

## 五、角色权限归入菜单树

### 5.1 问题

角色编辑对话框中，"权限分配"和"菜单分配"是两个独立区域。权限按 resource 分组以卡片网格展示，菜单以树形展示，两者缺乏关联，用户难以直观理解某菜单下有哪些可分配的操作权限。

### 5.2 解决方案

将权限复选框嵌入到 `el-tree` 的自定义节点中，通过菜单路径 → 权限 resource 的约定映射实现关联。

### 5.3 映射逻辑

```
菜单路径末段 → 权限 resource

/system/users       → user
/system/roles       → role
/system/permissions → permission
/system/menus       → menu
/tasks              → task
/files              → file
/analysis           → analysis
/settings/llm       → llm
/rag                → rag
```

无菜单路径或无法匹配的菜单节点不显示权限复选框。

### 5.4 核心实现

**辅助函数**：

```typescript
const pathToResource: Record<string, string> = {
  users: 'user', roles: 'role', permissions: 'permission', menus: 'menu',
  tasks: 'task', files: 'file', analysis: 'analysis', llm: 'llm', rag: 'rag',
}

function getMenuResource(menu: any): string | null {
  if (!menu.path) return null
  const seg = menu.path.split('/').filter(Boolean).pop() || ''
  return pathToResource[seg] || null
}

function getPermsForMenu(menu: any): { id: number; name: string; action: string }[] {
  const resource = getMenuResource(menu)
  if (!resource) return []
  const group = permissionGroups.value.find(g => g.resource === resource)
  return group?.permissions || []
}

function togglePerm(permId: number, checked: boolean) {
  if (checked) {
    if (!form.permissionIds.includes(permId)) form.permissionIds.push(permId)
  } else {
    form.permissionIds = form.permissionIds.filter(id => id !== permId)
  }
}
```

**模板结构**：

```
菜单与权限
├── el-alert (提示)
└── el-tree (show-checkbox, default-expand-all)
    └── #default slot (自定义节点)
        ├── menu-node-label (菜单名称)
        ├── menu-node-path (路径, 等宽字体灰色标签)
        └── menu-node-perms (权限复选框组)
            └── el-checkbox × N
                ├── perm-inline-name (权限名称)
                └── perm-inline-action (操作标签, 如 create/edit/delete)
```

**关键交互**：权限复选框区域使用 `@click.stop` 阻止事件冒泡，防止点击权限时触发菜单节点的选中/展开行为。
