# AI 简历筛选系统 — 需求分析与架构设计

## 概述

基于与豆包（AI 助手）的深度对话，梳理「利用招聘网站爬取数据 + AI 模型做简历筛选」的完整业务逻辑、技术路线、以及当前项目已具备的能力和后续缺口。

核心目标：做一套 AI 简历筛选系统，给企业 HR 使用。输入求职者简历 → 系统自动匹配岗位、打分排序 → HR 只看高分简历。

---

## 一、三类数据及其定位

| 数据类型 | 角色 | 用途 |
|---------|------|------|
| 外网爬取岗位 JD | 模型底座 | 建技能词库、岗位分类、训练通用语义模型 |
| 本单位自有岗位 JD | 筛选标尺 | 定硬性门槛（学历/年限/必备技能）、定制化权重 |
| 求职者简历 | 被评估对象 | 结构化解析 → 向量化 → 匹配打分 |

核心思路：外网数据训通用模型 + 本单位数据定企业专属规则 + 简历做匹配打分 + 结构化筛选，三层叠加。

---

## 二、第一阶段：用爬取外部岗位数据打底（5 步）

### Step 1 — 数据采集与字段规整
把爬取的杂乱 JD 固定成结构化字段：
- 岗位名称、岗位职责、任职要求
- 学历要求、工作年限、技能关键词
- 行业、城市、薪资区间

### Step 2 — 文本预处理
- 清洗：去空格、特殊符号、广告话术
- 分词：jieba / 大模型领域分词
- 停用词过滤：去掉「吃苦耐劳、责任心强」等无筛选价值的废话

### Step 3 — 构建技能词库 + 同义词库
从海量 JD 提取高频技能、岗位名词，用聚类/语义相似度合并同义说法：
- 后端开发 = 服务端开发 = 后台开发
- 运维 = 系统运维 = Linux 运维
- 大数据 = 数仓 = 数据开发

**这就是 AI 数据增强的核心价值。**

### Step 4 — 岗位聚类与分类体系
- Word2Vec / BERT 将每个 JD 转向量
- KMeans / 层次聚类自动归类
- 产出通用岗位分类树：互联网 → 后端 → Java后端、Go后端、运维…

### Step 5 — 训练通用岗位语义向量模型
- 微调 Sentence-BERT / 直接训练行业语义向量
- 每个岗位大类生成标准岗位向量模板
- 向量输入公式：岗位名称 + 岗位职责 + 任职要求

## 三、爬取数据步骤 ↔ AI 数据增强对照

| 爬取岗位数据操作 | 对应 AI 数据增强类型 |
|-----------------|-------------------|
| 多平台同岗位批量爬 JD | 样本数量增强 |
| 技能 / 岗位同义词归一 | 同义词替换增强 |
| 不同公司同岗位话术差异 | 语义复述 / 句式增强 |
| 补齐冷门岗位语料 | 小样本类别增强 |
| 全网 JD 训练向量模型 | 增强语料模型预训练 |

**核心认知**：不同公司同岗位，JD 话术完全不一样但语义相同——这种天然差异等同于 AI 数据增强里的「语义复述、句式改写」，省去了用大模型人工生成增强数据的成本。

## 五、标准岗位向量模型所需字段

### 基础标识字段
- `job_id`：岗位唯一 ID
- `job_source`：数据来源（爬取 / 本单位内部）
- `job_category_l1/l2/l3`：一级/二级/三级分类
- `job_city`：工作城市
- `job_salary_min/max`：薪资区间

### 核心文本字段（向量原料）
- `job_name`：岗位名称（权重最高）
- `job_duty`：岗位职责描述
- `job_requirement`：任职要求（最重要）
- `job_background`：公司行业/业务方向

### 结构化抽取字段（规则过滤 + 向量加权）
- `edu_require`：学历要求
- `work_year_require`：工作年限要求
- `skill_list`：归一化技能标签列表
- `cert_list`：证书要求
- `major_list`：专业要求
- `work_type`：全职/兼职/实习

### 向量存储字段
- `job_embedding`：岗位整体语义向量（768/1024维）
- `job_name_embedding`：岗位名称单独向量（粗匹配）
- `job_skill_embedding`：技能集合向量（精准匹配）
- `vector_version`：模型版本号

### 最小可用字段集（只做基础匹配）
`job_id`, `job_name`, `job_category_l2`, `job_duty`, `job_requirement`, `skill_list`, `edu_require`, `work_year_require`, `job_embedding`

## 六、完整落地方案（需后续开发）

### 三层筛选逻辑

**第一层：通用匹配（外网爬取数据）**
- 简历向量 与 外网岗位向量做相似度计算
- 自动识别候选人适合什么岗位大类
- 兜底分类，筛掉完全职业不匹配的人

**第二层：本单位 JD 精准匹配（内部岗位数据）**
- 硬规则过滤：学历、年限、专业、必备技能不满足直接淘汰
- 语义精准打分：简历向量 与 本单位岗位 JD 向量计算相似度
- 定制权重加分：本单位看重的技能/行业/项目经历额外加权

**第三层：综合排序与可解释结果**
- 输出合格/不合格标签、匹配分数排名
- 标出缺失技能、优势亮点、风险点

### HR 使用流程
1. HR 录入/选择本单位招聘岗位 JD
2. 系统自动依托外网模型理解岗位、补齐技能同义词
3. 批量导入简历，系统自动初筛 + 打分排序
4. HR 只看高分合格简历

## 七、后续待建设模块

1. **简历解析模块**：非结构化简历（PDF/Word）→ 结构化字段（学历、年限、技能栈、项目经验、证书、跳槽频次）
2. **匹配打分引擎**：规则过滤（硬性条件）+ 向量相似度（软性匹配）融合打分公式
3. **本单位岗位 JD 管理**：录入内部岗位，设定专属硬规则和加分权重
4. **HR 操作后台**：上传简历 → 自动筛选 → 打分排序 → 导出结果

---

## 八、关键设计决策

- **模型方案**：Sentence-BERT 做语义向量 + pgvector 存储 + 余弦相似度匹配
- **匹配策略**：三层递进 — 通用岗位分类（粗筛）→ 本单位规则过滤（硬淘汰）→ 语义精准打分（排序）
- **合规边界**：只爬公开 JD 文本，不爬个人隐私，内部使用不商用倒卖
- **AI 不可替代人工的环节**：面试价值观判断、沟通能力评估、企业文化匹配
