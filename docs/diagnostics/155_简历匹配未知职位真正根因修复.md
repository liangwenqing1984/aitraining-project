# 简历匹配显示"未知职位"——真正根因修复

## 概述

此前通过 LEFT JOIN + COALESCE 修复后，用户上传简历匹配结果仍然全部显示"未知职位"。经排查数据库数据完全正确（367条记录无一空值），真正根因在于前后端字段命名不一致。

---

## 一、现象

上传简历文件 → 匹配返回结果 → 所有职位名称显示"未知职位"，公司名称为空。

---

## 二、根因

PostgreSQL 返回 `snake_case` 列名，但 `database.ts` 中的 `convertToCamelCase` 函数会在查询结果返回前将所有字段名转为 `camelCase`：

| DB 原始列名 | 转换后 | 前端取值 |
|------------|--------|---------|
| `job_name` | `jobName` | `item.job_name` ❌ undefined |
| `company_name` | `companyName` | `item.company_name` ❌ undefined |
| `job_category_l1` | `jobCategoryL1` | `item.job_category_l1` ❌ undefined |
| `work_city` | `workCity` | `item.work_city` ❌ undefined |
| `text_content` | `textContent` | `item.text_content` ❌ undefined |

前端模板 `ResumeScreening.vue` 中所有字段均使用蛇形命名取值，因为 `item.job_name` 永远为 `undefined`，`item.job_name || '未知职位'` 永远落入兜底值。

## 三、修复

[ResumeScreening.vue](code/frontend/src/views/rag/ResumeScreening.vue) 模板中 8 处字段引用全部从 snake_case 改为 camelCase：

- `item.job_name` → `item.jobName`
- `item.company_name` → `item.companyName`
- `item.job_category_l1` → `item.jobCategoryL1`
- `item.job_category_l2` → `item.jobCategoryL2`
- `item.company_industry` → `item.companyIndustry`
- `item.work_city` → `item.workCity`
- `item.text_content` → `item.textContent`
- `:key="item.job_id"` → `:key="item.jobId"`
