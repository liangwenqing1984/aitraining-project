# 简历系统去重与导出修复及稳定性增强

## 概述

本次变更覆盖简历筛选系统的 10 个文件，解决 4 类核心问题：数据去重（文件级 + 结果级）、camelCase 字段访问导致的导出空值、LLM 调用超时与重试、前端上传交互与智能查询体验优化。

## 一、简历文件去重（MD5 哈希）

### 需求/问题
同一份简历文件多次上传会在 `sp_resumes` 产生重复记录，导致简历库冗余。

### 实现
- **`database.ts`**：`sp_resumes` 新增 `file_hash VARCHAR(64)` 列 + 唯一索引 `idx_resumes_file_hash`，含迁移脚本 `ADD COLUMN IF NOT EXISTS`
- **`ragController.ts` — `parseResume`**：上传时先计算文件 MD5，命中则直接从 DB 读取完整已解析数据返回（`SELECT *`），JSON 字段自动 parse
- **`ragController.ts` — `batchParseResumes`**：同上逻辑，统计 `duplicateCount`

### 关键代码
```ts
const fileHash = crypto.createHash('md5').update(file.buffer).digest('hex');
const existing = await db.prepare('SELECT * FROM sp_resumes WHERE file_hash = ?').get(fileHash);
if (existing) { /* 返回完整已解析数据，含 duplicate: true */ }
```

## 二、筛选结果去重（唯一约束 + Upsert）

### 需求/问题
同一份简历对同一个岗位多次筛选会在 `sp_screening_results` 产生多条记录。

### 实现
- **`database.ts`**：`DO $ BEGIN ... END $` 安全添加唯一约束 `uq_screening_resume_job UNIQUE (resume_id, internal_job_id)`
- **`ragController.ts` — `saveScreeningResult`**：INSERT 改为 `ON CONFLICT (resume_id, internal_job_id) DO UPDATE SET` 全部字段 + `created_at = CURRENT_TIMESTAMP`
- 支持每条结果携带自己的 `resumeId`（从 `_resumeId` 获取），配合 `resumeNameCache` Map 批量缓存查询

## 三、camelCase 字段访问修复

### 需求/问题
`database.ts` 的 `convertToCamelCase()` 全局将所有 snake_case DB 字段转为 camelCase，但多处代码仍用下划线命名取值，全部拿到 `undefined`。

### 修复清单

| 文件 | 函数 | 修复字段数 |
|------|------|-----------|
| `ragController.ts` | `exportScreeningExcel` | 9 个（resumeName/internalJobTitle/totalScore/hardRulesPassed/educationPassed/experiencePassed/skillsPassed/skillBonus/createdAt） |
| `ragController.ts` | `exportResumesExcel` | 12 个（educationLevel/graduationYear/workYears/desiredPosition/desiredCity/desiredSalaryMin/desiredSalaryMax/jobType/selfEvaluation/parseConfidence/originalFilename/createdAt） |
| `trainingController.ts` | `deleteTrainingJob` | 1 个（modelOutputPath） |

## 四、LLM 调用稳定性

### 4.1 超时控制
- **`cloud.ts` / `local.ts`**：新增 60s 默认超时，`AbortController` + `setTimeout`/`clearTimeout` 模式
- **`llm.ts`（前端）**：`executeNLQuery` axios 超时 30s → 120s

### 4.2 简历解析递进重试
- **`resumeParser.ts`**：推理模型思考消耗大导致 content 为空时，自动递进重试 3 次，maxTokens [16384 → 32768 → 49152]，每次失败日志记录，全部失败后抛出明确错误

## 五、智能查询页体验优化

### 需求/问题
- 每次提问自动重启会话，无法新建
- 历史会话无法删除
- 30s 超时频繁触发

### 修复
- **`query/Index.vue`**：新增"新建查询"按钮 (`newQuery()` 清空当前会话) + 每条历史右侧删除按钮 (`handleDeleteHistory` with `ElMessageBox.confirm`)
- 导入 `Delete` 图标、`deleteNLQuery` API、`ElMessageBox`

## 六、简历上传交互修复

### 6.1 `el-upload` drag 模式重复触发
- **现象**：上传 2 份简历，解析结果出现 4 条
- **根因**：Element Plus `drag` 模式下 `on-change` 事件重复触发
- **修复**：`processingUids` Set 用 `file.uid` 做去重，`clearFile` 时清空

### 6.2 `file.raw` 为空静默退出
- **现象**：上传文件后前端无任何反应
- **修复**：`!file.raw` 时显式输出 `console.error` + `ElMessage.error`，不再静默 return

### 6.3 重复简历展示完整解析数据
- **现象**：已解析过的简历上传后不展示结构化字段
- **修复**：后端返回 `SELECT *` 全字段数据，JSON 字段 parse 后再返回

### 6.4 多简历筛选导出
- **`exportCurrentScreening`**：导出前先自动保存到历史（失败不影响导出），支持传多个 `resumeIds`
- **`exportScreeningExcel`（后端）**：新增 `resumeIds` 参数，支持 `IN (...)` 批量查询

## 七、前端其他优化
