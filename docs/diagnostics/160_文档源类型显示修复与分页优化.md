# 文档源类型显示修复与分页优化

## 概述

修复 AI 问答机器人文档索引"源类型分布"始终显示 1 类的 bug，为模型训练页面补充分页功能，新增模型删除 API，并优化诊断日志。

## 一、文档源类型显示修复

### 需求/问题
问答机器人左侧面板显示"已索引 3173 片段（1 类源）"，实际数据库存在 6 类源（用户手册/诊断文档/设计文档/后端源码/前端源码/帮助文档）。

### 实现/修复
**根因**：`database.ts` 的 `convertToCamelCase()` 将 PG 返回的 `source_type` 转为 `sourceType`，但 `docIndexService.ts` 的 `getDocIndexStats()` 仍用 `r.source_type`（snake_case）访问。转换后字段恒为 `undefined`，fallback `|| 'doc_section'` 将所有类型合并为 1 类。

**修复文件**：[`code/backend/src/services/docIndexService.ts`](code/backend/src/services/docIndexService.ts#L640-L651)
- `getDocIndexStats()`: `r.source_type` → `r.sourceType`
- `searchDocs()`: `r.source_type`/`r.file_path` → `r.sourceType`/`r.filePath`
- `keywordSearch()`: 同上

**修复后** API 正确返回 6 类源分布。

## 二、问答机器人源类型展示优化

### 需求/问题
源类型显示简陋，仅显示"X 类源"数字，无法直观了解各类型详情。

### 实现/修复
**修复文件**：[`code/frontend/src/views/aibot/Index.vue`](code/frontend/src/views/aibot/Index.vue#L249-L270)
- `el-tooltip` 替换为 `el-popover`，hover 展示详细分布
- 每种源类型使用 `el-tag` 带颜色标识（成功/警告/危险/信息色）
- 无来源数据时显示 fallback "1 类源"

## 三、模型训练列表分页

### 需求/问题
系统管理 → 模型训练页面，Tab 1（训练数据集）和 Tab 3（已训练模型）列表无分页。

### 实现/修复
**修复文件**：[`code/frontend/src/views/system/ModelTraining.vue`](code/frontend/src/views/system/ModelTraining.vue)
- 引入 `computed`，添加 `paginatedDatasets` / `paginatedModels` 计算属性
- 表格 `:data` 改为计算属性数组 sliced 结果
- 各表格下方追加 `el-pagination` 组件，默认每页 10 条

## 四、模型删除 API

### 需求/问题
训练输出目录存在孤儿模型文件（训练失败/中断产生），缺乏清理入口。

### 实现/修复
- 后端：[`trainingController.ts`](code/backend/src/controllers/trainingController.ts#L347-L376) 新增 `deleteModel`，含路径穿越安全检查，`fs.rmSync` 递归删除模型目录
- 路由：[`trainingRoutes.ts`](code/backend/src/routes/trainingRoutes.ts#L19) 注册 `DELETE /models/:name`
- 前端 API：[`training.ts`](code/frontend/src/api/training.ts) 新增 `deleteModel(name)` 方法

## 五、诊断日志增强

### 实现/修复
- [`docSourceScanner.ts`](code/backend/src/services/docSourceScanner.ts)：输出项目根目录、待扫描配置列表、各目录检查结果（含绝对路径）
