# 126 — CSS 变量级联修复固定列透明：终极方案

## 问题背景

经过 5+ 轮 CSS 修复（!important、background 简写、body 前缀提特异性、background-color 双写、cell-style 内联），任务列表固定列（操作列）仍然透明，导致"创建时间"列内容穿透叠加。

## 根因分析

Element Plus 表格固定列使用 `var(--el-table-bg-color)` 设置单元格背景：

```css
/* Element Plus 内部（简化） */
.el-table td.el-table__cell {
  background-color: var(--el-table-bg-color);
}
```

全局玻璃主题将变量设为 `transparent`：
```css
.el-table {
  --el-table-bg-color: transparent;
}
```

之前所有修复方案都试图用 **CSS 选择器** 覆盖固定列 DOM 元素的 `background` 属性。但实际效果不稳定，可能原因：
1. Vite HMR 对非 scoped `<style>` 块的热更新不可靠
2. 浏览器 CSS 缓存
3. Element Plus 内部样式优先级难以完全覆盖

## 终极方案：内联 style + CSS 变量级联

**核心原理**：CSS 自定义属性会沿 DOM 树向下级联。固定列虽然是独立渲染的 DOM 子树，但仍位于 `<el-table>` 根元素内部。在根元素上用内联 style 设置变量，子元素通过 `var()` 引用时自然获得新值。

**实现**：
```html
<el-table 
  :style="{ 
    '--el-table-bg-color': '#fafafa', 
    '--el-table-tr-bg-color': '#fafafa' 
  }"
  ...>
```

**为什么之前的 cell-style 无效**：Element Plus 的 `cell-style` 可能不会应用到固定列的独立 DOM 节点。

**为什么这个方案可靠**：
1. 内联 style 优先级最高（高于任何样式表）
2. CSS 变量通过级联传播，不受选择器特异性影响
3. 固定列 DOM 是 `el-table` 后代，自然继承变量
4. 不依赖 Vite HMR 对 style 块的处理

## 涉及文件

| 文件 | 修改 |
|------|------|
| `code/frontend/src/views/crawler/Index.vue` | 任务列表 el-table 加 `:style` CSS 变量 |
| `code/frontend/src/views/files/Index.vue` | 文件列表 el-table 加 `:style` CSS 变量 |

## 保留的防御层

全局 CSS（style.css）和组件非 scoped CSS 的固定列不透明规则保留作为兜底。
