# 数据看板模块诊断指南

## 架构一览

```
浏览器                        Express 后端                  PostgreSQL
───────                      ────────────                 ──────────
Dashboard.vue  ──GET──>  /api/dashboard/overview  ──>  sp_job_enrichments
 (ECharts)      <──JSON──  dashboardController      <──  sp_jobs
```

单次请求返回 9 个聚合维度 + 5 项汇总指标，前端拆分为 8 张图表 + 5 张统计卡片渲染。

---

## 一、API 层诊断

### 1.1 请求失败（HTTP 5xx）

**现象**：看板页面一直 loading 或显示"加载失败"

**排查步骤**：

```bash
# ① 直接 curl 看报错
curl -s http://localhost:3001/api/dashboard/overview | head -200

# ② 看后端控制台输出
# 关键日志前缀：[DB] Query all error
```

**常见原因与修复**：

| 错误信息关键词 | 原因 | 修复 |
|---------------|------|------|
| `column ... must appear in the GROUP BY clause` | SQL 中 SELECT/ORDER BY 使用了未出现在 GROUP BY 中的列 | 改为按原始列分组，JS 侧格式化显示名 |
| `relation "sp_job_enrichments" does not exist` | 未执行数据库初始化或表缺失 | 重启后端触发 `initDatabase()` |
| `column "xxx" does not exist` | 字段名拼写错误或 snake_case/camelCase 混淆 | 检查 `database.ts` 的 `convertToCamelCase` 转换逻辑 |

### 1.2 数据全为 0 或空数组

**现象**：API 返回 `success: true`，但 `totalJobs: 0`，所有图表空白

**排查**：

```sql
-- 检查是否有增强过的数据
SELECT COUNT(*) FROM sp_job_enrichments;

-- 检查具体字段是否为 NULL
SELECT 
  COUNT(*) as total,
  COUNT(salary_monthly_min) as has_salary,
  COUNT(education_normalized) as has_edu,
  COUNT(company_industry) as has_industry
FROM sp_job_enrichments;
```

如果 `has_salary` 为 0，说明数据尚未经过 AI 增强。需先运行爬虫 → 再进行数据增强。

### 1.3 薪资分布桶全为 0

**根因**：`salary_monthly_min` 全部为 NULL。

**验证 SQL**：
```sql
SELECT salary_monthly_min, salary_monthly_max, COUNT(*) 
FROM sp_job_enrichments 
WHERE salary_monthly_min IS NOT NULL 
GROUP BY salary_monthly_min, salary_monthly_max 
LIMIT 10;
```

### 1.4 城市分布为空

城市数据来自 `sp_jobs.work_city`（原始爬取数据），非 `sp_job_enrichments`。如果表中有 `sp_jobs` 但 `work_city` 全为 NULL，说明爬虫未正确提取城市字段。

```sql
SELECT work_city, COUNT(*) FROM sp_jobs GROUP BY work_city LIMIT 10;
```

## 二、前端诊断

### 2.1 页面一直 loading

**排查**：

1. 打开浏览器 DevTools → Network，看 `/api/dashboard/overview` 请求状态：
   - **pending** → 后端无响应，检查后端是否启动
   - **500** → 后端报错，按第一章排查
   - **200 但无数据** → 检查响应体 `data` 字段
2. 检查控制台是否有 JS 报错

### 2.2 图表卡片空白但数据已返回

**现象**：顶部统计卡片有数值，但下方某张图表区域空白

**常见原因**：

| 原因 | 排查方法 |
|------|----------|
| DOM 元素未挂载 | `chartRefs['xxx']` 为 `undefined` |
| `echarts.init()` 未调用 | 控制台搜 `Cannot read properties of undefined` |
| 图表容器高度为 0 | 检查 `.chart-box` 的 `flex: 1` 是否生效，父容器是否有明确高度 |
| 数据格式不对 | 控制台打印 `data.value.xxx` 查看实际数据 |

**快速诊断**：在浏览器控制台执行
```js
// 检查某张图表的 DOM 尺寸
document.querySelector('.chart-box').getBoundingClientRect()
// height 应为正数，若为 0 则 CSS 布局有问题
```

### 2.3 统计卡片 NaN 或 undefined

**现象**：卡片显示 `NaN` 或 `-`

**原因**：对应字段为 `null` 或 `undefined`。检查 API 返回的 `summary` 对象：
```js
// 控制台
fetch('/api/dashboard/overview').then(r=>r.json()).then(d=>console.log(d.data.summary))
```

### 2.4 窗口缩放后图表变形

`resizeCharts()` 仅对已初始化的实例生效。如果某图表因数据为空未初始化，后续窗口 resize 不会报错。

若出现图表未随窗口缩放，检查该图表是否在 `charts` 对象中：
```js
// 控制台
Object.keys(charts)  // 应包含 salary, city, education, experience, industry, category, workMode, skills
```

### 2.5 饼图标签重叠

如果某分类占比过小（< 3%），ECharts 默认仍显示标签导致重叠。可在 `series.label` 中增加 `hideOverlap: true` 或提高 `radius` 外半径。

## 三、性能诊断

### 3.1 API 响应慢（> 3s）

**根因**：`/api/dashboard/overview` 单次执行 10+ 条 SQL，每条可能全表扫描。

**排查**：

```sql
-- 检查各表行数
SELECT 
  (SELECT COUNT(*) FROM sp_job_enrichments) as enrichments,
  (SELECT COUNT(*) FROM sp_jobs) as jobs;

-- 检查是否有必要索引
SELECT indexname FROM pg_indexes WHERE tablename = 'sp_job_enrichments';
```

**优化方向**：
- 确保 `sp_job_enrichments.task_id` 有索引
- 对高频 GROUP BY 列（`company_industry`、`education_normalized`、`job_category_l1`）添加单列索引
- 超过 10 万行数据考虑物化视图定时刷新

### 3.2 前端渲染慢

8 张 ECharts 图表同时初始化，每张都会触发 DOM 布局计算。

**优化方向**：
- 对非首屏图表使用 `IntersectionObserver` 延迟初始化
- 大数据量图表（技能词云）限制展示条数（当前已限 TOP 15）

## 四、数据一致性诊断

### 4.1 汇总数与图表数对不上

看板顶部的 `totalJobs` 来自：
```sql
SELECT COUNT(*) FROM sp_job_enrichments WHERE salary_monthly_min IS NOT NULL
```

而各图表数据来自各自的 GROUP BY 查询，若某个图表维度全为 NULL，其数据量会少于 `totalJobs`。这是**预期行为**，不是 bug。

### 4.2 平均薪资与直觉不符

`avgSalary` 计算方式：`AVG((salary_monthly_min + salary_monthly_max) / 2.0)`

如果存在极端值（如把"日薪 300"错标为月薪 300），会拉偏均值。可执行诊断 SQL：
```sql
SELECT salary_monthly_min, salary_monthly_max, job_id 
FROM sp_job_enrichments 
WHERE salary_monthly_min < 1000 OR salary_monthly_max > 100000
ORDER BY salary_monthly_min;
```

## 五、错误码速查

| 错误码 | 含义 | 排查要点 |
|--------|------|----------|
| `42803` | GROUP BY 缺少列 | 检查 SQL 的 SELECT/ORDER BY 中所有非聚合列是否都在 GROUP BY 中 |
| `42703` | 字段不存在 | 检查 snake_case/camelCase 命名 |
| `42P01` | 表不存在 | 数据库未初始化 |
| `ECONNREFUSED` | 后端未启动 | 检查 `node dist/index.js` 进程 |
| `Network Error`（前端） | CORS 或后端未启动 | 检查 Vite 代理配置及后端端口 |

## 六、快速健康检查脚本

```bash
#!/bin/bash
# 数据看板健康检查
ENDPOINT="http://localhost:3001/api/dashboard/overview"

echo "=== 数据看板健康检查 ==="
echo ""

# 1. 连通性
STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$ENDPOINT")
echo "HTTP状态码: $STATUS"

if [ "$STATUS" != "200" ]; then
  echo "❌ API 不可达"
  exit 1
fi

# 2. 数据结构
BODY=$(curl -s "$ENDPOINT")
SUCCESS=$(echo "$BODY" | grep -o '"success":true')
if [ -z "$SUCCESS" ]; then
  echo "❌ 响应 success 不为 true"
  echo "$BODY" | head -5
  exit 1
fi

# 3. 核心指标
TOTAL=$(echo "$BODY" | grep -o '"totalJobs":[0-9]*' | grep -o '[0-9]*')
CITIES=$(echo "$BODY" | grep -o '"cityDistribution":\[' | wc -l)
CHARTS=$(echo "$BODY" | grep -o '"Distribution":\[' | wc -l)

echo "✅ API 正常"
echo "  总职位数: $TOTAL"
echo "  城市数据: $([ "$CITIES" -gt 0 ] && echo '有' || echo '无')"
echo "  分布图表数: $CHARTS"
```

将此脚本保存为 `check_dashboard.sh`，出问题时先跑一遍。
