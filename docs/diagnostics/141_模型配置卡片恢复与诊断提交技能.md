# 模型配置卡片显示恢复与诊断提交技能

## 概述

本次变更包含两项：LLM 模型配置页面左侧供应商卡片显示恢复为原始行为，以及创建"诊断文档 + 提交 + 合并"自动化技能。

## 一、模型配置卡片恢复

### 问题
上轮迭代将供应商卡片改为每条配置独立展示（模型名作为卡片标题），用户反馈左侧应显示供应商名（如 Ollama），右侧远程模型应显示各个供应商名，不显示具体模型名。

### 修复
`LLMSettings.vue` 中 `remoteCards` 和 `localCards` 计算属性回退：

- **本地卡片**：始终显示一张 "Ollama" 卡片，配置后将模型名作为副标题
- **远程卡片**：每个供应商一张卡片（DeepSeek、OpenAI 等），配置后将首个模型名作为副标题
- 点击配置过的卡片编辑该供应商的首个配置

```typescript
// remoteCards: 按供应商去重，每供应商一张卡片
const providerConfigMap = new Map<string, LLMConfig>()
configs.value.filter(c => c.provider !== 'ollama' && c.isActive).forEach(c => {
  if (!providerConfigMap.has(c.provider)) providerConfigMap.set(c.provider, c)
})

// localCards: 始终展示一张 Ollama 卡片
const ollamaConfig = configs.value.find(c => c.provider === 'ollama' && c.isActive)
```

## 二、诊断提交技能

### 需求
将"编写诊断文档 → 提交代码 → 推送到远程 → 合并到主分支"这一重复操作制作为可复用的技能。

### 实现
创建 `.agents/skills/diagnose-doc-commit/skill.md`，定义 7 步流程：

1. 检查 git 状态（status / diff / log）
2. 编写编号诊断文档（递增编号，涵盖所有变更模块）
3. 暂存文件（排除敏感和生成文件）
4. 中文规范提交信息（type + 标题 + 列表）
5. 推送到当前分支远程
6. 合并到 main + 推送 main
7. 确认结果报告

触发条件：用户说"提交代码"、"提交到远程"、"合并到主分支"。
