# 数据看板 AI 全量洞察与系统优化总结

## 概述

本次迭代包含以下核心变更：数据看板 AI 全量洞察报告（生成 + PDF 下载）、文本向量化模型可配置化、多供应商多配置支持、爬虫卡片样式统一、PDF 生成方式优化。

## 一、数据看板 AI 全量洞察报告

### 需求
数据看板需要一个基于**全部任务全量数据**的 AI 洞察报告，而非基于单个任务。报告需支持在线预览和 PDF 下载。

### 后端实现

#### 1. 全量数据聚合 `insights.ts`

新增 `buildAllStats()` 和 `generateAllInsights()` 函数：

```typescript
// 与单任务报告的关键区别：
// - 不加 task_id 过滤，查询所有 sp_job_enrichments 数据
// - file_id 和 task_id 设为 '__all__' 标记为全量报告
// - report_type = 'overview_all'
```

聚合维度包括：总职位数、城市覆盖数、公司总数、薪资分布、学历分布、经验要求分布、职位分类、热门技能 Top 20、行业分布、工作模式分布、数据来源分布。

#### 2. API 端点 `dashboardRoutes.ts`

```typescript
POST   /api/dashboard/insights                     // 生成全量洞察报告
GET    /api/dashboard/insights/history              // 获取历史报告列表
GET    /api/dashboard/insights/report/:reportId     // 获取单个报告详情
GET    /api/dashboard/insights/report/:reportId/pdf // 下载报告 PDF
```

#### 3. 数据库外键约束修复

`sp_market_reports.file_id` 原有外键约束 `REFERENCES sp_csv_files(id)`，全量报告的 `file_id='__all__'` 不在该表中，导致插入失败。

**修复**：在 `database.ts` 的 `initDatabase()` 中添加：
```sql
ALTER TABLE sp_market_reports DROP CONSTRAINT IF EXISTS market_reports_file_id_fkey
```

### 前端实现 `dashboard/Index.vue`

在黑龙江省区域分布下方新增 AI 洞察报告面板，包含：
- 历史报告下拉选择器
- "生成洞察报告"按钮（loading 状态 + 进度提示）
- 报告摘要（渐变背景 + 左侧蓝色边框）
- Markdown 内容渲染（支持表格、标题、列表、粗体、代码）
- 关键发现高亮块（橙色左侧边框）
- PDF 下载按钮
- 空状态引导文案

## 二、文本向量化模型可配置化

### 变更

将 embedding 模型从硬编码 `nomic-embed-text` 改为通过 LLM 模型配置系统管理。

### 涉及文件

| 文件 | 变更 |
|------|------|
| `types/index.ts` | LLMTaskType 新增 `'embedding'`，新增 `EmbeddingResult` 接口 |
| `services/llm/index.ts` | LLMService 新增 `embed()` 方法和 `getConfigForTask()` 公开化 |
| `services/llm/providers/cloud.ts` | CloudProvider 新增 `embed()` → `POST /v1/embeddings` |
| `services/llm/providers/local.ts` | LocalProvider 新增 `embed()` → `POST /api/embeddings` |
| `services/llm/embeddings.ts` | 优先从 llmService 获取配置，失败回退到本地 Ollama |
| `views/settings/LLMSettings.vue` | 任务路由新增"文本向量化"选项 |

## 三、多供应商多配置支持

### 问题
一个供应商（如 Ollama）只能配置一条模型记录，无法同时用 `qwen3:14b` 做数据增强和 `nomic-embed-text` 做文本向量化。

### 修复
`LLMSettings.vue` 卡片系统重写：
- 每个已配置的模型显示独立卡片（标题=模型名，副标题=供应商名）
- 未配置的供应商显示占位卡片
- 默认 Ollama 路由改为 `['enrichment', 'anti-crawl']`（移除了 embedding）

## 四、PDF 生成方案优化

### 问题
Puppeteer 24.41.0 依赖 Chrome 147，系统 Chrome 版本为 137，版本不匹配导致：
1. 直接下载 Chrome 因网络限制失败
2. 使用系统 Chrome 时 PDF 文件损坏（6.19MB 无法打开）

### 解决方案
放弃 Puppeteer，改用 Chrome 原生命令行 `--headless --print-to-pdf`：

```typescript
// 核心流程：
// 1. HTML 写入临时文件
// 2. execFile 调用 Chrome --headless --print-to-pdf=<output>
// 3. 读取 PDF buffer → 发送响应
// 4. finally 清理临时文件
```

优势：不依赖 puppeteer 版本，兼容任意系统 Chrome。

## 五、爬虫页面卡片样式统一

### 变更
`StatCard.vue` 组件样式与数据看板卡片完全一致：
- 白色背景 + `border: 1px solid #f0f0f0` + 轻微阴影
- 图标区 40×40px + 纯色背景 + `border-radius: 10px`
- 数值 `font-size: 32px` + `font-weight: 700` + `color: #303133`
- 标签 `font-size: 13px` + `color: #909399`
- hover 效果 `translateY(-2px)` + 增强阴影

去除了：玻璃拟态效果、顶部彩色条、图标发光、图标 hover 缩放、标签大写转换。

### 布局
`crawler/Index.vue` 统计卡片区域从 `el-row/el-col` 改为 CSS Grid：
```css
.stat-row {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 16px;
}
```
