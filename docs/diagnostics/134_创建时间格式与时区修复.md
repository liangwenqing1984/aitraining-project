# 创建时间格式与时区修复

> 日期：2026-05-08
> commit: `cd2c625`

## 一、问题现象

用户管理、角色管理、权限管理等模块列表中，创建时间列显示为：

```
2026-05-08T03:12:54.095Z
```

期望格式：北京时间纯文本，不带时区后缀：
```
2026-05-08 11:12:54
```

## 二、根因分析

问题由两层叠加导致：

### 第一层：PostgreSQL 连接未设时区

`CURRENT_TIMESTAMP` / `NOW()` 返回服务器所在时区时间（通常 UTC），而非北京时间。存入 `TIMESTAMP`（无时区）列后，值是 UTC 时间，比北京时间晚 8 小时。

### 第二层：pg 驱动 Date 序列化

pg 驱动将 `TIMESTAMP` 列值解析为 JavaScript `Date` 对象。当 Express 通过 `JSON.stringify()` 序列化响应时，`Date` 对象调用 `toISOString()` 方法，强制输出 UTC 时间并附加 `Z` 后缀。

```
PG 返回:  "2026-05-08 11:12:54.095"  (北京时间)
   ↓ pg 驱动
JS Date:  2026-05-08T03:12:54.095Z   (Date 内部为 UTC)
   ↓ JSON.stringify()
输出:     "2026-05-08T03:12:54.095Z"  (带 Z 的 ISO 格式)
```

即使先将 PG 时区设为 Asia/Shanghai（第一层修复），第二层的 Date 序列化仍会产生问题格式。

## 三、修复方案

### 修复 1：PG 连接时区设置

`database.ts` 两处添加 `SET timezone = 'Asia/Shanghai'`：

**连接池级别** — 每个新连接自动执行：
```typescript
pool.on('connect', (client) => {
  client.query("SET timezone = 'Asia/Shanghai'")
    .catch(err => console.error('[DB Pool] 设置时区失败:', err.message));
});
```

**初始化连接** — `initDatabase()` 建表前：
```typescript
await client.query("SET timezone = 'Asia/Shanghai'");
```

效果：`CURRENT_TIMESTAMP` 返回 `2026-05-08 11:12:54.095`（北京时间）。

### 修复 2：重写 pg 类型解析器

绕过 Date 对象，直接返回纯字符串：

```typescript
import { Pool, types } from 'pg';

// OID 1114 = TIMESTAMP (without timezone)
// PG 返回: "2026-05-08 11:12:54.095"
// 处理后: "2026-05-08 11:12:54"
types.setTypeParser(1114, (value: string) => {
  return value.replace(/\.\d+$/, '');
});

// OID 1184 = TIMESTAMPTZ (with timezone)
// PG 返回: "2026-05-08 11:12:54.095+08"
// 处理后: "2026-05-08 11:12:54"
types.setTypeParser(1184, (value: string) => {
  return value.replace(/\.\d+.*$/, '');
});
```

### 完整数据流（修复后）

```
PG:       CURRENT_TIMESTAMP → "2026-05-08 11:12:54.095"  ← 北京时间
   ↓ types.setTypeParser(1114)
后端:     "2026-05-08 11:12:54"                           ← 纯字符串
   ↓ JSON.stringify()
前端:     "2026-05-08 11:12:54"                           ← 无时区后缀
```

## 四、前端兼容性

现有前端代码分为两类场景：

### 直接显示（不受影响）

系统管理页面使用 `<el-table-column prop="createdAt">` 直接渲染字符串，无任何转换。

### Date 构造调用

| 文件 | 用法 | 兼容性 |
|------|------|--------|
| `analysis/Index.vue:134` | `new Date(latest.createdAt).getTime()` | ✅ 浏览器本地时区（北京）正确解析 |
| `analysis/Index.vue:1243` | `new Date(r.createdAt).toLocaleDateString('zh-CN')` | ✅ 仅取日期部分 |
| `files/Index.vue:24` | `new Date(dateStr)` | ✅ 格式化函数内部容错处理 |
| `query/Index.vue:162` | `new Date(ts)` | ✅ 自定义格式化 |

`new Date('2026-05-08 11:12:54')`（空格分隔格式）在现代浏览器中解析为本地时区时间，用户浏览器在北京时区，解析结果正确。

## 五、影响范围

- 所有 `TIMESTAMP` / `TIMESTAMPTZ` 列的读取全部返回字符串
- 全表影响：sp_users, sp_roles, sp_permissions, sp_menus, sp_tasks, sp_csv_files, sp_market_reports, sp_saved_queries, sp_job_embeddings 等
- 后端无 `new Date(createdAt)` 类型操作，不受影响
- 前端日期操作均为浏览器本地时区，兼容正确

## 七、注意事项

- 修复前写入的旧记录（UTC 时间）仍会显示为旧值，如需批量修正可执行 `UPDATE sp_xxx SET created_at = created_at + INTERVAL '8 hours' WHERE created_at < '2026-05-08 00:00:00'`
- `types.setTypeParser` 作用于进程全局，无需每个查询重复设置
