# 简历筛选匹配

## 功能目标

实现简历上传 → LLM 结构化解析 → 入库 → 与内部岗位三级融合匹配（硬性规则 + 向量语义 + 技能加分），输出推荐等级和分数，支持筛选历史管理和 Excel 导出。

## 业务流程

### 简历上传解析

```
上传 PDF/DOCX/TXT → 文本提取(mammoth/pdf-parse)
  → 文件 MD5 去重检查 → LLM 结构化解析(DeepSeek V4 Pro)
  → 解析出21个字段 → INSERT INTO sp_resumes
  → 异步生成 768维向量 → UPDATE sp_resumes SET embedding
```

### 人岗匹配筛选

```
选择简历(或输入文本) → 生成简历向量(三路降级)
  → 获取招聘中岗位列表(sp_internal_jobs, status='open')
  → 逐岗位计算: 硬性规则(40分) + 语义相似度(40分) + 技能加分(20分)
  → 排序(硬规则优先 → 总分降序) → 返回Top N + 推荐等级
```

## 三级匹配引擎

### 1. 硬性规则检查（满分 40，不通过则 0）

| 维度 | 规则 | 说明 |
|------|------|------|
| 学历 | 简历等级 ≥ 岗位要求等级 | 高中(1)<大专(2)<本科(3)<硕士(4)<博士(5) |
| 经验 | 简历年限 ≥ 岗位要求最低年限 | 岗位无要求则默认通过 |
| 技能 | 简历技能 ∩ 岗位必备技能 | 支持 all/any 两种模式 |

### 2. 向量语义相似度（满分 40）

```
简历向量 ↔ 岗位向量 → 余弦相似度 × 100 → 0-100分 → ×0.4 → 0-40分
```

### 3. 技能加分（满分 20）

```
必备技能命中 × 3 + 加分技能命中 × 2 = 技能加分（上限 20）
```

### 推荐等级

| 总分 | 等级 | 含义 |
|------|------|------|
| ≥ 80 | strong | 强烈推荐 |
| ≥ 60 | moderate | 一般推荐 |
| ≥ 40 | weak | 勉强推荐 |
| < 40 | rejected | 不推荐 |

## Embedding 三路降级策略

```
1. 结构化区分性文本（期望岗位+技能+学历+专业+项目）
   ↓ 为空时
2. 原始简历文本（前 2000 字符）
   ↓ 为空时
3. 预存向量（sp_resumes.embedding，兼容旧数据）
   ↓ 仍为空时
4. 纯硬性规则匹配（语义相似度 = 0）
```

## 业务规则

- **文件去重**：MD5 哈希去重，相同文件不重复解析（返回已有记录）
- **文件限制**：支持 .docx/.pdf/.txt/.doc，最大 10MB
- **批量上传**：多文件并发解析，前端去重展示
- **岗位限制**：仅匹配 `status='open'` 的岗位
- **强制排序**：硬性规则通过者优先，同级按总分降序

## 数据关联

- `sp_resumes`：简历库（raw_text + 结构化字段 + embedding vector(768)）
- `sp_internal_jobs`：内部岗位（required_skills/preferred_skills/education_required/embedding vector(768)）
- `sp_screening_results`：筛选结果历史（scores + ranks）

## 异常处理

- 文件格式不支持 → 返回 400 `"不支持的文件格式"`
- 简历文本 < 10 字符 → 返回 400 `"解析出的简历文本内容太短"`
- 无招聘中岗位 → 返回 400 `"没有可匹配的内部岗位"`
- LLM 解析失败 → 返回 500 + 错误详情
- embedding 生成失败 → 降级使用预存向量或纯规则匹配

## 验收标准

- [ ] 上传 PDF/DOCX/TXT 简历成功解析出结构化字段

- [ ] 推荐等级（strong/moderate/weak/rejected）正确
